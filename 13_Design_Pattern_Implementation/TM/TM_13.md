## Deskripsi
**Event Delegation dalam JavaScript**

**Pendahuluan**

Dalam pengembangan aplikasi web, kita sering berinteraksi dengan banyak elemen HTML yang dapat memicu suatu peristiwa (*event*), seperti klik tombol, pengisian formulir, pergerakan mouse, dan sebagainya. Cara yang paling sederhana untuk menangani peristiwa tersebut adalah dengan memasang *event listener* secara langsung pada setiap elemen yang ingin diamati.

Sebagai contoh:

```javascript
const buttons = document.querySelectorAll('.btn');

buttons.forEach(button => {
  button.addEventListener('click', () => {
    console.log('Button diklik');
  });
});
```

Pendekatan ini bekerja dengan baik jika jumlah elemen sedikit dan tidak berubah. Namun, ketika jumlah elemen sangat banyak atau elemen dibuat secara dinamis setelah halaman dimuat, pendekatan tersebut menjadi kurang efisien. Untuk mengatasi masalah inilah digunakan teknik yang disebut **Event Delegation**.

---

**Apa Itu Event Delegation?**

Event Delegation adalah teknik dalam JavaScript yang memanfaatkan mekanisme **event bubbling** untuk menangani event dari banyak elemen melalui satu *event listener* yang dipasang pada elemen induknya (*parent element*).

Alih-alih memasang listener pada setiap elemen anak, kita hanya memasang satu listener pada parent. Ketika sebuah event terjadi pada elemen anak, event tersebut akan "naik" (*bubble up*) ke parent dan dapat ditangani dari sana.

Dengan kata lain, parent bertindak sebagai perwakilan (*delegate*) yang menerima dan mengelola event dari seluruh elemen anaknya.

---

**Konsep Dasar: Event Bubbling**

Untuk memahami Event Delegation, kita harus memahami terlebih dahulu konsep **Event Bubbling**.

Misalkan terdapat struktur HTML berikut:

```html
<div id="container">
  <button id="btn">Klik Saya</button>
</div>
```

Ketika tombol diklik, browser tidak hanya mengirim event ke tombol tersebut. Event akan bergerak dari elemen yang diklik menuju elemen-elemen induknya.

Urutannya:

```text
button
↓
div
↓
body
↓
html
↓
document
```

Proses naiknya event dari elemen target menuju induknya inilah yang disebut **event bubbling**.

Karena event akan sampai ke parent, maka parent dapat mengetahui bahwa salah satu anaknya memicu event.

---

**Cara Kerja Event Delegation**

Perhatikan contoh berikut.

HTML:

```html
<ul id="menu">
  <li>Beranda</li>
  <li>Produk</li>
  <li>Kontak</li>
</ul>
```

Tanpa Event Delegation:

```javascript
const items = document.querySelectorAll('li');

items.forEach(item => {
  item.addEventListener('click', () => {
    console.log(item.textContent);
  });
});
```

Pada kode di atas, setiap elemen `<li>` memiliki listener sendiri.

Dengan Event Delegation:

```javascript
const menu = document.getElementById('menu');

menu.addEventListener('click', event => {
  if (event.target.tagName === 'LI') {
    console.log(event.target.textContent);
  }
});
```

Sekarang hanya terdapat satu listener pada elemen `<ul>`.

Ketika pengguna mengklik salah satu `<li>`, event akan naik ke `<ul>`, lalu listener pada `<ul>` memeriksa elemen mana yang sebenarnya diklik menggunakan:

```javascript
event.target
```

---

**Peran `event.target`**

Dalam Event Delegation, properti yang paling penting adalah:

```javascript
event.target
```

Properti ini menunjukkan elemen yang sebenarnya memicu event.

Contoh:

```html
<ul id="menu">
  <li>Home</li>
  <li>About</li>
</ul>
```

Jika pengguna mengklik elemen "About":

```javascript
menu.addEventListener('click', event => {
  console.log(event.target);
});
```

Output:

```html
<li>About</li>
```

Bukan `<ul>`, melainkan elemen yang benar-benar diklik.

Inilah yang memungkinkan satu listener menangani banyak elemen sekaligus.

---

**Contoh pada Elemen Dinamis**

Salah satu alasan utama penggunaan Event Delegation adalah untuk menangani elemen yang dibuat setelah halaman dimuat.

Misalnya:

```html
<ul id="list"></ul>
```

```javascript
const list = document.getElementById('list');

list.addEventListener('click', event => {
  if (event.target.tagName === 'LI') {
    console.log(event.target.textContent);
  }
});

const item = document.createElement('li');
item.textContent = 'Item Baru';
list.appendChild(item);
```

Walaupun elemen `<li>` baru ditambahkan setelah listener dibuat, event tetap dapat ditangani.

Jika menggunakan cara biasa:

```javascript
item.addEventListener(...)
```

maka setiap elemen baru harus dipasangi listener secara manual.

Event Delegation menghilangkan kebutuhan tersebut.

---

**Menggunakan `matches()`**

Dalam praktik modern, biasanya digunakan metode:

```javascript
event.target.matches()
```

Contoh:

```javascript
menu.addEventListener('click', event => {
  if (event.target.matches('li')) {
    console.log(event.target.textContent);
  }
});
```

Pendekatan ini lebih fleksibel dibandingkan memeriksa `tagName`.

---

**Menggunakan `closest()`**

Kadang-kadang elemen yang diklik berada di dalam elemen target.

Contoh:

```html
<li>
  <span>Produk</span>
</li>
```

Jika pengguna mengklik `<span>`, maka:

```javascript
event.target
```

akan mengembalikan `<span>`, bukan `<li>`.

Solusinya:

```javascript
const item = event.target.closest('li');
```

Contoh:

```javascript
menu.addEventListener('click', event => {
  const item = event.target.closest('li');

  if (item) {
    console.log(item.textContent);
  }
});
```

Teknik ini lebih aman dan sering digunakan dalam aplikasi nyata.

---

**Mengapa Disebut Delegation?**

Kata "delegation" berarti pendelegasian tugas.

Dalam pola ini:

* Elemen anak tidak menangani event sendiri.
* Tanggung jawab tersebut didelegasikan kepada parent.

Ilustrasinya:

```text
Tanpa Delegation

Button 1 → Listener
Button 2 → Listener
Button 3 → Listener
Button 4 → Listener

Dengan Delegation

Button 1 ┐
Button 2 ├── Parent → Listener
Button 3 ┤
Button 4 ┘
```

Parent menjadi pusat pengelolaan event.

---

**Keuntungan Event Delegation**

**1. Menghemat Memori**

Tanpa delegation:

```javascript
1000 elemen = 1000 listener
```

Dengan delegation:

```javascript
1000 elemen = 1 listener
```

Penggunaan memori menjadi lebih efisien.

---

**2. Kode Lebih Sederhana**

Kita tidak perlu melakukan perulangan untuk memasang listener pada setiap elemen.

---

**3. Mendukung Elemen Dinamis**

Elemen yang dibuat setelah halaman dimuat tetap dapat ditangani tanpa konfigurasi tambahan.

---

**4. Pemeliharaan Lebih Mudah**

Perubahan logika cukup dilakukan pada satu tempat.

---

**Kekurangan Event Delegation**

**1. Tidak Semua Event Mendukung Bubbling**

Beberapa event tidak melakukan bubbling secara normal, misalnya:

```javascript
focus
blur
```

Untuk kasus tersebut diperlukan pendekatan khusus.

---

**2. Membutuhkan Pemeriksaan Target**

Karena semua event diterima oleh parent, kita harus memeriksa elemen mana yang sebenarnya memicu event.

---

**3. Struktur DOM yang Kompleks**

Jika struktur HTML sangat dalam, logika identifikasi target dapat menjadi lebih rumit.

---

**Hubungan dengan Design Pattern**

Meskipun Event Delegation lebih sering dianggap sebagai teknik penanganan event daripada design pattern formal seperti Singleton atau Factory, konsep ini mencerminkan prinsip penting dalam desain perangkat lunak, yaitu **centralized event handling**.

Alih-alih setiap objek mengelola event sendiri, satu objek pusat bertanggung jawab mengelola event dari banyak objek lain. Pendekatan ini mengurangi coupling, meningkatkan efisiensi, dan membuat sistem lebih mudah dipelihara.

Framework modern seperti React, Vue, dan berbagai library UI juga memanfaatkan konsep serupa untuk mengelola event secara efisien.

---

**Kesimpulan**

Event Delegation adalah teknik JavaScript yang memanfaatkan mekanisme event bubbling untuk menangani event dari banyak elemen melalui satu event listener pada elemen induk. Dengan menggunakan `event.target`, parent dapat mengetahui elemen mana yang memicu event dan menjalankan logika yang sesuai.

Teknik ini memberikan berbagai keuntungan seperti penggunaan memori yang lebih efisien, kode yang lebih sederhana, kemudahan menangani elemen dinamis, serta pemeliharaan yang lebih baik. Oleh karena itu, Event Delegation menjadi salah satu teknik yang sangat penting dalam pengembangan aplikasi web modern, terutama ketika bekerja dengan banyak elemen interaktif atau elemen yang dibuat secara dinamis.
