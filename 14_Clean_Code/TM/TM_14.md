## Tugas
Dari dua kode di bawah ini, mana yang kamu ingin cari masalahnya dan perbaiki di tengah-tengah malam, katakanlah jam 1 malam? Mengapa?
```javascript
function processUser(user) {
  if (user) {
    if (user.isActive) {
      if (user.hasPermission) {
        return doSomething(user)
      }
    }
  }
  return null
}
```
```javascript
function processUser(user) {
  if (!isValidCandidate(user)) return null;
  return doSomething(user);
}

function isValidCandidate(user) {
  return user && user.isActive && user.hasPermission;
}
```
## Deskripsi

Dalam situasi pemeliharaan sistem atau proses debugging yang mendesak, kode kedua lebih disarankan dibandingkan kode pertama karena memiliki struktur yang lebih sederhana, mudah dipahami, dan lebih sesuai dengan prinsip *Clean Code*.

**Kode Pertama**

```javascript
function processUser(user) {
  if (user) {
    if (user.isActive) {
      if (user.hasPermission) {
        return doSomething(user)
      }
    }
  }
  return null
}
```

**Kode Kedua**

```javascript
function processUser(user) {
  if (!isValidCandidate(user)) return null;
  return doSomething(user);
}

function isValidCandidate(user) {
  return user && user.isActive && user.hasPermission;
}
```

**Analisis Perbandingan**

**1. Tingkat Keterbacaan yang Lebih Baik**

Kode kedua memiliki alur yang lebih jelas karena menggunakan fungsi dengan nama yang deskriptif.

```javascript
if (!isValidCandidate(user)) return null;
```

Nama fungsi `isValidCandidate()` secara langsung menjelaskan tujuan dari proses validasi tanpa mengharuskan pembaca memahami seluruh detail implementasi terlebih dahulu.

Sebaliknya, pada kode pertama, pembaca harus menelusuri beberapa tingkat percabangan untuk memahami kondisi yang diperlukan sebelum fungsi `doSomething()` dijalankan.

**2. Mengurangi Kompleksitas Akibat Nested Conditional**

Kode pertama menggunakan beberapa tingkat *nested if*.

```javascript
if (user) {
  if (user.isActive) {
    if (user.hasPermission) {
      return doSomething(user)
    }
  }
}
```

Struktur seperti ini meningkatkan kompleksitas pembacaan dan menyulitkan proses analisis ketika jumlah kondisi bertambah.

Kode kedua menghilangkan *nested conditional* dengan memindahkan logika validasi ke fungsi terpisah sehingga alur utama menjadi lebih sederhana.

**3. Penerapan Separation of Concerns**

Kode kedua memisahkan tanggung jawab ke dalam fungsi yang berbeda.

```javascript
function processUser(user) {
  if (!isValidCandidate(user)) return null;
  return doSomething(user);
}
```

```javascript
function isValidCandidate(user) {
  return user && user.isActive && user.hasPermission;
}
```

Fungsi `processUser()` bertanggung jawab mengatur alur proses, sedangkan fungsi `isValidCandidate()` bertanggung jawab melakukan validasi data pengguna. Pemisahan ini membuat kode lebih mudah dipelihara dan dikembangkan.

**4. Kemudahan Modifikasi**

Apabila terdapat kebutuhan baru, misalnya pengguna harus memiliki email yang telah terverifikasi, kode kedua dapat diperbarui dengan lebih mudah.

```javascript
function isValidCandidate(user) {
  return (
    user &&
    user.isActive &&
    user.hasPermission &&
    user.emailVerified
  );
}
```

Perubahan cukup dilakukan pada satu fungsi tanpa memengaruhi alur utama program.

Pada kode pertama, penambahan kondisi baru akan meningkatkan tingkat *nesting* dan memperumit struktur kode.

**5. Kemudahan Pengujian**

Fungsi validasi pada kode kedua dapat diuji secara independen.

```javascript
isValidCandidate(user);
```

Pengujian terpisah memungkinkan proses verifikasi logika dilakukan dengan lebih cepat dan terstruktur tanpa harus menjalankan keseluruhan proses bisnis.

**Kesimpulan**

Kode kedua lebih unggul dari segi keterbacaan, pemeliharaan, pengujian, dan pengembangan. Penggunaan fungsi yang deskriptif, pengurangan *nested conditional*, serta penerapan prinsip *Separation of Concerns* menghasilkan kode yang lebih mudah dipahami dan lebih efisien untuk proses debugging maupun pengembangan lanjutan. Oleh karena itu, kode kedua merupakan pilihan yang lebih baik untuk dipelihara dalam lingkungan pengembangan perangkat lunak profesional.
