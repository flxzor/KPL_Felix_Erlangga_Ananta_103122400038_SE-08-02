## Tugas
Kode ini tampak baik dan bagus, tetapi menyalahi beberapa prinsip kode bersih. Bisakah kamu melakukan refaktorisasi? Dimodifikasi dari [amrrwael/Delivery-website-Hits](https://github.com/amrrwael/Delivery-website-Hits).

Sebagai konteks, fungsi di bawah ini menampilkan rincian pesanan di modal dan jika klik konfirmasi, sistem apa menyimpannya.

```javascript
function fetchOrderDetails(orderId, token) {
    fetch(`https://example.com/api/order/${orderId}`, {
        headers: {
            'Authorization': token
        }
    })
    .then(response => {
        if (!response.ok) {
            throw new Error('Failed to fetch order details');
        }
        return response.json();
    })
    .then(order => {
        // Display order info
        const modal = document.getElementById('orderModal');
        const detailsDiv = modal.querySelector('#orderDetails');
        detailsDiv.innerHTML = '';

        const header = document.createElement('h3');
        header.textContent = `Order ID: ${order.id}`;
        detailsDiv.appendChild(header);

        const status = document.createElement('p');
        status.textContent = `Status: ${order.status}`;
        detailsDiv.appendChild(status);

        // Show modal
        modal.style.display = 'block';

        // Setup close button
        const closeBtn = modal.querySelector('.close');
        closeBtn.addEventListener('click', () => {
            modal.style.display = 'none';
        });

        // Setup confirm button
        const confirmBtn = modal.querySelector('#confirmOrderBtn');
        if (order.status === 'Delivered') {
            confirmBtn.style.display = 'none';
        } else {
            confirmBtn.addEventListener('click', () => {
                confirmOrder(order.id, token);
            });
        }
    })
    .catch(error => {
        console.error('Error:', error);
    });
}
```

## Deskripsi

**Refaktorisasi Fungsi** `fetchOrderDetails`

Kode yang diberikan berfungsi untuk mengambil detail pesanan dari API, menampilkan informasi pesanan pada modal, serta mengatur aksi konfirmasi pesanan. Meskipun kode tersebut berjalan dengan baik, terdapat beberapa pelanggaran terhadap prinsip *Clean Code* yang menyebabkan kode menjadi lebih sulit dipelihara, diuji, dan dikembangkan di masa depan.

**Analisis Permasalahan**

1. Fungsi Memiliki Terlalu Banyak Tanggung Jawab

Fungsi `fetchOrderDetails()` melakukan beberapa tugas sekaligus, yaitu:

* Mengambil data dari API.
* Menangani error request.
* Membuat dan mengubah elemen DOM.
* Menampilkan modal.
* Mengatur event listener tombol tutup.
* Mengatur event listener tombol konfirmasi.

Hal ini melanggar prinsip *Single Responsibility Principle (SRP)* karena satu fungsi seharusnya hanya memiliki satu alasan untuk berubah.

2. Event Listener Berpotensi Menumpuk

Pada setiap pemanggilan fungsi, kode berikut akan dijalankan kembali:

```javascript
closeBtn.addEventListener('click', () => {
    modal.style.display = 'none';
});

confirmBtn.addEventListener('click', () => {
    confirmOrder(order.id, token);
});
```

Jika pengguna membuka modal berkali-kali, maka event listener akan terus bertambah dan dapat menyebabkan fungsi dieksekusi lebih dari satu kali ketika tombol ditekan.

3. Penggunaan Magic String

Nilai status pesanan ditulis secara langsung:

```javascript
if (order.status === 'Delivered')
```

Penulisan seperti ini berisiko menimbulkan kesalahan pengetikan (*typo*) dan menyulitkan pemeliharaan ketika nilai status berubah.

4. Tingkat Kompleksitas Tinggi

Penggunaan beberapa `.then()` secara berurutan membuat alur program lebih sulit dibaca dibandingkan penggunaan `async/await`.

**Solusi Refaktorisasi**

Refaktorisasi dilakukan dengan memisahkan tanggung jawab fungsi ke beberapa fungsi yang lebih kecil, menggunakan `async/await`, serta menghindari penumpukan event listener.

```javascript
const ORDER_STATUS = {
    DELIVERED: 'Delivered'
};

async function fetchOrderDetails(orderId, token) {
    try {
        const order = await getOrderDetails(orderId, token);

        renderOrderDetails(order);
        showOrderModal(order, token);

    } catch (error) {
        console.error('Error:', error);
    }
}

async function getOrderDetails(orderId, token) {
    const response = await fetch(
        `https://example.com/api/order/${orderId}`,
        {
            headers: {
                Authorization: token
            }
        }
    );

    if (!response.ok) {
        throw new Error('Failed to fetch order details');
    }

    return response.json();
}

function renderOrderDetails(order) {
    const detailsDiv = document.querySelector('#orderModal #orderDetails');

    detailsDiv.innerHTML = `
        <h3>Order ID: ${order.id}</h3>
        <p>Status: ${order.status}</p>
    `;
}

function showOrderModal(order, token) {
    const modal = document.getElementById('orderModal');
    const closeBtn = modal.querySelector('.close');
    const confirmBtn = modal.querySelector('#confirmOrderBtn');

    modal.style.display = 'block';

    closeBtn.onclick = () => {
        modal.style.display = 'none';
    };

    configureConfirmButton(confirmBtn, order, token);
}

function configureConfirmButton(button, order, token) {
    const isDelivered =
        order.status === ORDER_STATUS.DELIVERED;

    button.style.display = isDelivered
        ? 'none'
        : 'block';

    if (!isDelivered) {
        button.onclick = () => {
            confirmOrder(order.id, token);
        };
    }
}
```

**Penjelasan Hasil Refaktorisasi**

1. Memisahkan Tanggung Jawab Fungsi

Fungsi besar dipecah menjadi beberapa fungsi kecil:

* `getOrderDetails()` bertanggung jawab mengambil data dari API.
* `renderOrderDetails()` bertanggung jawab menampilkan informasi pesanan ke halaman.
* `showOrderModal()` bertanggung jawab menampilkan modal.
* `configureConfirmButton()` bertanggung jawab mengatur perilaku tombol konfirmasi.

Pendekatan ini membuat kode lebih mudah dibaca dan dipelihara.

2. Menggunakan Async/Await

Sebelumnya kode menggunakan:

```javascript
fetch(...)
    .then(...)
    .then(...)
    .catch(...)
```

Setelah refaktorisasi:

```javascript
try {
    const order = await getOrderDetails(orderId, token);
} catch (error) {
    console.error(error);
}
```

Struktur ini lebih mudah dipahami karena alur eksekusi terlihat seperti kode sinkron biasa.

3. Menghindari Penumpukan Event Listener

Sebelumnya:

```javascript
confirmBtn.addEventListener('click', ...);
```

digunakan setiap kali modal dibuka.

Setelah refaktorisasi:

```javascript
button.onclick = () => {
    confirmOrder(order.id, token);
};
```

Penggunaan `onclick` akan menggantikan handler sebelumnya sehingga tidak terjadi penumpukan event listener.

4. Menghilangkan Magic String

Nilai status pesanan dipindahkan ke konstanta:

```javascript
const ORDER_STATUS = {
    DELIVERED: 'Delivered'
};
```

Sehingga pengecekan status menjadi:

```javascript
order.status === ORDER_STATUS.DELIVERED
```

Pendekatan ini meningkatkan konsistensi dan mempermudah perubahan di masa depan.

**Kesimpulan**

Refaktorisasi yang dilakukan meningkatkan kualitas kode dengan menerapkan prinsip *Single Responsibility Principle*, mengurangi kompleksitas fungsi, mencegah penumpukan event listener, serta meningkatkan keterbacaan melalui penggunaan `async/await`. Hasil akhirnya adalah kode yang lebih bersih (*clean*), mudah dipelihara (*maintainable*), dan lebih mudah dikembangkan (*scalable*) dibandingkan implementasi awal.
